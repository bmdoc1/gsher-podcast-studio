# GSHER Podcast Studio — Production Deployment

**Status:** Deployment-ready package, NOT live. External GitHub/Render accounts and GSHER DNS/site editor have not been connected in this conversation.

## A. Deploy a private, durable web service

1. Create a **private GitHub repository** named `gsher-podcast-studio` and upload the contents of this directory as the repository root. Never commit the `.env` file, uploaded recordings, or live secrets.
2. Connect the GitHub repository to **Render**. Choose **New > Blueprint**, select the repo, and use its `render.yaml`.
3. Review the Render charge before creating the service. The blueprint requests a **paid Starter web service** plus a **10-GB persistent disk**; this is intentional because the default free filesystem is ephemeral.
4. Supply a unique `ADMIN_PASSWORD` in Render's environment variable prompt. `SESSION_SECRET` is generated by Render. Do not send administrator credentials in chat or store them in the repository.
5. When Render reports the deployment live, open its assigned HTTPS hostname (for example `https://gsher-podcast-studio.onrender.com/`) and confirm `/health` shows `{"ok": true}`. The actual assigned hostname should be copied from Render; do not assume this example is exact.
6. Test the "Studio admin" sign-in, create a **draft** test episode, upload a short consented audio clip and speaker photo, publish it, listen on a public/private browser, and reclassify it as Draft. Confirm its files are not publicly retrievable while it is a Draft.
7. Back up the persistent `/var/data/studio.sqlite3` database and `/var/data/uploads/` together. Schedule regular off-service backups. See security reminders below.

## B. Connect the dedicated subdomain

1. In Render service **Settings > Custom Domains**, add `podcast.globalselfhealthcare.org`.
2. At your domain DNS provider, add the exact CNAME Render requests:

   | Type | Name / Host | Points to |
   | --- | --- | --- |
   | `CNAME` | `podcast` | **the actual `[your-service].onrender.com` hostname shown in Render** |

3. Use Render's **Verify** button. Render issues/renews the TLS certificate. Wait for HTTPS and verify the listening library. **Do not change the DNS records of the root domain (`@`), `www`, or `learn`**; this is only a new `podcast` subdomain.

## C. Add to GSHER's website navigation

Edit the EXISTING GSHER website **only after** the podcast domain opens correctly:

- In the `Read & watch` menu, add **GSHER Podcasts** linking to `https://podcast.globalselfhealthcare.org/`.
- Optional homepage card: `Listen, learn and reflect — conversations about self-healthcare, CelluReva™, Project RESPECT and healthy living in English, Hindi and Odia.`
- Open links in a new tab if navigating out to the subdomain. Do **not** replace the existing Dr Biswajit Speaks, Odia Pathasala, Learning Academy or admin systems.
- Sample HTML is provided in `GSHER_HOMEPAGE_INTEGRATION.html`; website builders may require using their link editor instead of raw HTML.

## D. AI transcription and briefings (optional)

- In Render service environment, add `OPENAI_API_KEY` as a **secret**; this is not included in the repository.
- The **Transcribe uploaded recording** action extracts the **audio track only** with FFmpeg, compresses it, and sends it to the speech-to-text API. The model defaults to `gpt-transcribe`.
- The transcription API is subject to a maximum file size (25 MB). A compressed extracted audio track above the application's 24-MB threshold must be split by the editor or replaced with imported `.txt/.srt/.vtt` text.
- This cloud transcription presently returns plain text, not reliable per-sentence timestamps. For clickable timestamps, import time-coded `.srt`/`.vtt` or run optional local `faster-whisper` on a sufficiently powerful host.
- The **Generate AI briefing draft** action also uses the API key. Both actions incur additional API charges and require editorial review; speaker attribution is **manual**.
- Get informed permission before sending recordings or transcripts to third-party AI services. Do not submit patient-identifiable recordings without an approved privacy/legal basis.

## E. Before allowing a large public audience

- Add named staff accounts/MFA and an audit trail rather than sharing a single editor password.
- Add external backups, storage monitoring, upload malware scanning and a production observability/alerting setup.
- Obtain recorded consent for every speaker's recording, photograph and publication.
- Have medical content checked and clearly labeled as education, not personalized diagnosis/treatment.
- Use longer async transcription jobs for lengthy recordings if your hosting plan imposes request-duration limits; this starter processes a file transcription synchronously.

**Test before announcing the live address.** Merely possessing this package does not register the subdomain, provide hosting or alter GSHER's existing website.
